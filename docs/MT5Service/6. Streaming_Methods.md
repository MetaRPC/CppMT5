# MT5Service — Streaming Methods (Mid-Level)

> 5 real-time streams that deliver **friendly event structs** (times in UTC) to your callback on a background thread. Wrappers over [MT5Account Streaming](../MT5Account/7.%20Streaming_Methods/Streaming_Methods.Overview.md).

**🧩 API Layer:** **MID-LEVEL**. **Implementation:** `src/mt5_service.cpp`.

---

## 📋 The methods

| Method | Callback payload | Description |
|--------|------------------|-------------|
| `subscribeTicks(symbols, cb)` | `Tick` | Live ticks for the given symbols |
| `streamTradeUpdates(cb)` | `TradeEvent` | Orders/positions/deals appearing, changing, closing |
| `streamTransactions(cb)` | `TransactionEvent` | Detailed transaction log (request/transaction/result) |
| `streamPositionProfits(cb)` | `PositionProfitEvent` | Periodic position-profit snapshots |
| `streamOpenedTickets(cb)` | `TicketsSnapshot` | Periodic position + pending-order ticket snapshots |

Each returns a **`std::unique_ptr<ServiceStream>`**.

---

## 🧵 The streaming model (read first)

```cpp
auto stream = service.subscribeTicks({"EURUSD"}, [](const Tick& t) { /* ... */ });
// ... stream is live on a background thread ...
stream->stop();   // cancel and join the reader thread
```

* The SDK reads the server stream on a **dedicated background thread** and calls your `callback` per payload — already converted to a friendly struct with **UTC** times.
* **Keep the handle alive.** Destroying the `unique_ptr` (or calling `stop()`) cancels the stream.
* **The callback runs on the reader thread** — don't block it; guard shared state (`std::atomic` / mutex).
* `ServiceStream` API: `stop()`, `running()`, `count()` (payloads delivered), `lastError()`.

See the [gRPC Streaming](../All_Guides/GRPC_STREAM_MANAGEMENT.md) and [Concurrency Model](../All_Guides/SYNC_VS_ASYNC.md) guides.

## 📦 Event DTOs (selected)

```cpp
struct Tick { std::string symbol; int64_t time, timeMsc;   // UTC
              double bid, ask, last, volume; uint32_t flags; };

struct EventAccountInfo { int64_t login; double balance, credit, equity,
                          margin, freeMargin, marginLevel, profit; };

struct PositionProfitInfo { uint32_t index; int64_t ticket; std::string symbol; double profit; };
struct PositionProfitEvent {
    int type; std::string terminalGuid; EventAccountInfo account;
    std::vector<PositionProfitInfo> newPositions, updatedPositions, deletedPositions;
};

struct TicketsSnapshot {
    std::string terminalGuid;
    std::vector<int64_t> positionTickets, pendingOrderTickets;
    int64_t serverTime;            // UTC seconds
};
```

`TradeEvent` and `TransactionEvent` carry richer sub-structs (`TradeOrderInfo`, `TradePositionInfo`, `TradeHistory*Info`, `TradeTransaction`, `TradeRequestInfo`, `TradeResultInfo`) — all declared in `mt5_service.hpp`.

## 💡 Examples

### Live ticks

```cpp
#include <thread>
#include <chrono>

auto stream = service.subscribeTicks({"EURUSD","GBPUSD"}, [](const Tick& t) {
    std::printf("%s %.5f/%.5f\n", t.symbol.c_str(), t.bid, t.ask);
});
std::this_thread::sleep_for(std::chrono::seconds(10));
stream->stop();
```

### Live P&L

```cpp
auto s = service.streamPositionProfits([](const PositionProfitEvent& e) {
    for (const PositionProfitInfo& p : e.updatedPositions)
        std::printf("#%lld %s profit %.2f\n",
                    (long long)p.ticket, p.symbol.c_str(), p.profit);
    std::printf("account equity %.2f\n", e.account.equity);
});
```

### React to trade events

```cpp
auto s = service.streamTradeUpdates([](const TradeEvent& e) {
    if (!e.newPositions.empty())
        std::printf("opened %zu position(s)\n", e.newPositions.size());
    if (!e.disappearedPositions.empty())
        std::printf("closed %zu position(s)\n", e.disappearedPositions.size());
});
```

### Ticket-diff feed (lightweight)

```cpp
auto s = service.streamOpenedTickets([](const TicketsSnapshot& snap) {
    std::printf("%zu positions, %zu pending (UTC %lld)\n",
                snap.positionTickets.size(), snap.pendingOrderTickets.size(),
                (long long)snap.serverTime);
});
```

## 🔧 Rules

1. **Store the handle** for as long as you want events.
2. **Keep callbacks fast**; offload slow work and guard shared state.
3. **One stream, many symbols** for ticks.
4. **Stop on shutdown** — `stream->stop()` (or let the `unique_ptr` go out of scope).
